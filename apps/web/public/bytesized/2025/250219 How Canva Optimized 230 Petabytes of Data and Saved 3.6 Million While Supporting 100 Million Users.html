🔍 Background: Canva’s Data Challenge

With 15B+ designs created, Canva’s storage needs exploded. They needed a way to reduce costs without impacting user experience. Most user-generated content is accessed soon after creation, then rarely touched. AWS’s S3 Glacier Instant Retrieval provided a cost-effective solution with fast access.

💡 Key Stats:

📌 230PB+ total storage in Amazon S3
📌 80B+ objects migrated to S3 Glacier IR
📌 $3.6M in annual savings
📌 Break-even on transition cost in a few months

🛠️ What Happened?

Canva used S3 Storage Class Analysis to assess their data:

🚨 90% of data was in S3 Standard-IA but contributed only 30-40% of access volume.
🚨 Most data retrieval occurred within the first 15 days.
🚨 Transitioning all data blindly would cost $6M.

🛑 Root Causes

1️⃣ Over-Reliance on S3 Standard-IA

While cost-effective, IA storage was still costlier than necessary for infrequently accessed content.

2️⃣ High Object Transition Costs

Moving billions of objects incurs transition fees, requiring strategic migration.

3️⃣ Lack of Visibility into Access Patterns

Before S3 Storage Class Analysis, Canva had limited insights into retrieval behaviors.

🤔 Lessons Learned

1️⃣ Data Visibility is Critical

Use S3 Storage Class Analysis to track access trends before making storage decisions.

2️⃣ Optimize for Object Size

Canva prioritized buckets with 400KB+ objects for migration, ensuring faster ROI.

3️⃣ Plan for Transition Costs

A $1.6M upfront cost was necessary but paid off in 6 months.

🚀 Mastering S3 Storage: Cost-Saving Tricks, Tools, Links, and Best Practices

Optimizing S3 storage at scale requires a deep understanding of access patterns, cost structures, and retrieval needs. Whether you're managing petabytes of data or just starting with cloud optimization, these best practices will help you reduce costs, improve performance, and ensure long-term efficiency.

📌 1️⃣ Analyze Storage Patterns with AWS Tools

Before making any changes, leverage AWS tools to gain insights into your storage footprint:

  • Amazon S3 Storage Class Analysis (Docs) – Helps track access frequency over time to determine optimal storage class transitions.

  • AWS Cost Explorer (Docs) – Provides visibility into S3 spending and identifies areas for cost savings.

  • S3 Inventory Reports (Docs) – Generates detailed reports on objects stored, including their size, age, and access frequency.

  • Amazon CloudWatch Metrics for S3 (Docs) – Monitors request patterns, storage usage, and retrieval costs.

📌 2️⃣ Select the Right S3 Storage Classes

Amazon S3 offers multiple storage classes tailored to different access patterns:

  • S3 Standard – Best for frequently accessed data (e.g., templates, stock assets).

  • S3 Standard-IA (Infrequent Access) – For data that needs quick access but is accessed less often.

  • S3 Glacier Instant Retrieval – Ideal for archival storage that still requires millisecond retrieval times.

  • S3 Glacier Flexible Retrieval – Best for backups and logs that can tolerate minutes to hours of retrieval.

  • S3 Glacier Deep Archive – Cheapest option for long-term archiving with retrieval times of 12+ hours.

Use Lifecycle Policies to automatically transition data between storage classes based on access patterns (Learn More).

📌 3️⃣ Automate Data Lifecycle Management

Lifecycle policies automate the transition of objects between storage classes and deletion of outdated data. Best practices:

  • Move data to Standard-IA after 30 days if it sees less frequent access.

  • Migrate cold data to Glacier Instant Retrieval after 90 days for cost savings with fast retrieval.

  • Delete or archive unused objects after 180+ days to avoid accumulating unnecessary costs.

  • Use object tagging to apply different lifecycle policies to different datasets (AWS Guide).

📌 4️⃣ Reduce API and Retrieval Costs

Every access request costs money. Optimize usage by:

  • Batching GET requests instead of requesting single objects repeatedly.

  • Using S3 Select (Docs) to retrieve only needed data from large files.

  • Minimizing small object storage – Aggregating small objects into larger ones reduces per-object metadata costs.

  • Implementing caching layers with services like AWS CloudFront to avoid unnecessary S3 fetch requests.

📌 5️⃣ Optimize Object Size and Structure

  • Large objects (>128KB) benefit from IA/Glacier storage due to per-object billing.

  • Small objects (<128KB) are cheaper in Standard due to minimum storage costs in IA/Glacier.

  • Use multipart uploads (Docs) for large files to improve efficiency and avoid timeouts.

📌 6️⃣ Secure Your Storage

  • Enable S3 Versioning (Docs) to protect against accidental deletions.

  • Use S3 Object Lock (Docs) for regulatory compliance and WORM (Write Once Read Many) storage.

  • Enable AWS Identity and Access Management (IAM) best practices (Docs) to prevent unauthorized access.

  • Encrypt sensitive data using S3 Server-Side Encryption (SSE) or AWS KMS (Docs).

📌 7️⃣ Monitor and Continuously Optimize

Storage needs evolve over time. Regularly review your usage:

  • Set up Cost Allocation Tags (Docs) to track and report on storage costs.

  • Use Amazon Macie (Docs) for security and compliance scanning.

  • Run AWS Trusted Advisor (Docs) to get real-time cost optimization recommendations.

🎯 Key Takeaways

✅ Use S3 Storage Class Analysis to make informed decisions about storage class transitions.
✅ Implement Lifecycle Policies to automate data movement and optimize costs.
✅ Reduce API costs by batching requests and leveraging caching strategies.
✅ Optimize object size to minimize per-object overhead in long-term storage.
✅ Secure your data with encryption, versioning, and IAM best practices.
✅ Monitor continuously using AWS Cost Explorer, CloudWatch, and Trusted Advisor.
