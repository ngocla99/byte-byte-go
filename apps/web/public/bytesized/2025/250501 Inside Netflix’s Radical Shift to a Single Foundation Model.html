Scaling personalized recommendations from siloed models to a single foundation engine

🚨 TL;DR

Netflix was juggling a swarm of specialized models to recommend content: one for your homepage, another for notifications, another for the “Because You Watched” row. Each was trained separately, each optimized in isolation. This worked until the costs, complexity, and inconsistencies became impossible to manage.

They rebuilt from the ground up: a single foundation model trained on the full timeline of user interaction across the platform. Instead of learning short-term behavior, this system learns long-term intent. It can generate predictions in milliseconds, adapt to new titles without training data, and serve as a shared source of embeddings for downstream teams.

This edition breaks down how Netflix structured the system, where they hit limits, and what challenges you’d face applying foundation models to recommendation at scale.

🧠 The Old Architecture: A Model for Every Use Case

For years, Netflix operated what you’d expect from a mature recommender system: many models, each designed for a narrow goal.

  • Ranking notifications: Personalized based on recent watch history

  • Homepage rows: Top Picks, Continue Watching, Trending each ranked by separate pipelines

  • Search re-ranking: Suggestions fine-tuned by intent

While the models were performant in isolation, the cracks showed over time:

  • Inconsistent personalization: Two parts of the UI might recommend completely different genres

  • Repeated feature engineering: Same features rebuilt in multiple training pipelines

  • Costly innovation: Improvements in one model rarely transferred to others

  • Short-term bias: Most models only used recent activity due to latency limits

In short, the personalization system didn’t scale with the platform or its audience.

🧱 The Foundation Model Approach

Instead of patching the existing system, Netflix moved to a foundation model paradigm—training a single, large model on the entirety of each user’s interaction history.

This meant shifting away from task-specific models and building a general-purpose engine that could:

  • Understand evolving preferences over time

  • Generate embeddings for members and content

  • Serve multiple use cases (search, homepage, notifications)

  • Adapt quickly to new titles, even before user interaction

The analogy to large language models fits: where LLMs predict the next token in a sentence, this model predicts the next title in a user’s content journey.

But recommendation is structurally different from language. The challenges run deeper.

🧮 Modeling Behavior as Tokens

At the core of the system is how user behavior is represented.

Netflix breaks down interaction history into tokens, each containing structured context:

  • What was watched (title ID, genre, metadata)

  • How long (watch duration, skip behavior, pause/resume)

  • When (time of day, day of week)

  • Where (device, location, UI surface)

These tokens are not uniform. A 2-hour movie and a 30-second preview are modeled differently. Netflix built a domain-specific tokenizer to compress noisy clickstream data into rich, high-utility sequences.

This is a crucial difference from LLMs. Tokens in text are discrete and bounded (words, subwords). In recommendation, the model ingests an open-ended stream of heterogeneous, user-generated events.

To avoid bloated sequences, Netflix uses:

  • Hierarchical compression: Merging multiple interactions on the same title into one token

  • Feature embedding: Embedding time-based and categorical features inside the token itself

  • Sliding window sampling: During training, overlapping segments of the sequence are sampled to ensure all history is covered over epochs

These steps keep sequences manageable while preserving long-term structure.

⚙️ Serving at Speed

Transformer-based models are notoriously compute-heavy. But recommendations have latency budgets, users won’t wait two seconds for a page to load.

Netflix designed the system to serve in tens of milliseconds. Here’s how:

  • Sparse attention: Instead of full attention over the sequence, the model uses a sparse pattern to restrict attention to local windows and key summary tokens

  • Key-Value caching: Previous tokens’ hidden states are cached during inference to avoid recomputation

  • Batch pre-computation: Embeddings for users and content are periodically computed offline and served via vector stores

By the time a user opens Netflix, much of the personalization work is already done. What’s left is a fast scoring pass against a pre-filtered candidate set.

❄️ Cold Starts: Recommending the Unknown

New content arrives on Netflix daily. You can’t wait for engagement data before recommending it. That’s the cold start problem—and it’s nontrivial.

Netflix tackles it with metadata-based initialization:

  1. Each new title is described by metadata: genre, tone, country, actors, production year, etc.

  2. Each metadata type has a learned embedding. These are combined (often via attention) to form a proxy embedding for the title.

  3. The title also receives a dedicated ID embedding, initialized with noise or using similarity heuristics to existing titles.

  4. A mixing layer balances the metadata and ID-based components, using title age as a signal.

New titles lean heavily on metadata embeddings. As viewership grows, the ID embedding gradually takes over.

This lets the foundation model recommend a brand-new Korean action series to the right users on launch day—before anyone’s watched it.

🔧 Lessons for System Designers

Netflix’s design offers guidance for teams working on personalization systems under scale and product pressure.

1. Compress Behavior Into Tokens Thoughtfully
Don’t dump raw logs into a model. Decide what actions matter, and embed context directly into the tokens.

2. Long Sequences Need Structure
Use sparse attention and hierarchical sampling to balance sequence length and expressiveness.

3. Don't Wait for Labels
Use auxiliary targets (genre, duration, skip) and multi-token objectives to learn richer representations from implicit feedback.

4. Stable Embeddings Matter
Embeddings used by downstream teams must be consistent across retrains. Netflix uses low-rank orthogonal transformations to maintain embedding stability over time.

5. Offline Compute Buys You Online Speed
Precompute as much as possible. If your system can’t hit latency targets, move heavy lifting upstream and cache results.

🧩 Unique Challenges in Applying Foundation Models to Recommendation

LLMs taught the industry a lot. But not everything ports over cleanly.

1. Entity Drift

In NLP, your vocabulary is stable. In recommendation, your vocabulary (the item catalog) changes daily. Thousands of titles are added or removed every week. Embeddings must be generated and integrated without retraining the full model.

2. Interaction Heterogeneity

LLMs process uniform tokens. Recommender models see variable-length, multi-modal, and multi-intent data. A single “watch” event could mean bingeing six episodes or trying something for two minutes. Tokens must encode both action and context to disambiguate intent.

3. Feedback Loops and Presentation Bias

In language models, the next word is objective. In recommendation, what’s shown affects what gets clicked. Netflix mitigates this using randomized slates, de-biasing pipelines, and evaluation strategies that isolate causal lift.

4. Unaligned Serving Needs

Different product surfaces want different behaviors: search needs speed and precision, the homepage wants breadth, and push notifications need timeliness. One model must serve them all while preserving specialization through fine-tuned heads or adapters.

5. Embedding Lifecycle Management

When models retrain weekly or monthly, old embeddings can lose semantic alignment. But thousands of services downstream still depend on them. This demands strong versioning, embedding hygiene, and compatibility tools to prevent breakages.

🧾 Final Word

This rebuild was both a modeling challenge and an infrastructure shift.

By replacing dozens of task-specific models with a unified foundation, Netflix cut down on duplication, enabled feature reuse, and created a single personalization backbone that can adapt, scale, and evolve.

Foundational models aren’t just for text and images. When built right, they can capture human intent across time, turning noisy, sparse interactions into meaningful predictions.

If your recommendation system feels cobbled together, if you’re repeating work across teams, or if you're bottlenecked by latency and cold starts—there’s a playbook here worth stealing.
